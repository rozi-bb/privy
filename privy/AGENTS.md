Instructions for AI coding assistants working in this repository.

Do not copy content from those documents into this file. Link to them.

## How we work

The project owner is learning and must be able to explain every part of this codebase in an interview. Optimize for understanding, not speed.

- Before writing code for a feature, explain the plan and the reasoning, then wait for approval.
- After writing, explain each new or changed file in plain language.
- Build one feature at a time. Evaluate it before starting the next.
- Follow the structure generated by the LangGraph template. Do not reorganize it.
- Verify LangChain and LangGraph APIs against the official docs (the `docs-langchain` and `reference-langchain` MCP servers) before using them. This project uses LangChain/LangGraph v1 APIs.

## Stack

- Python 3.13, managed with `uv`
- LangGraph 1.x, LangChain 1.x
- Chat model: DeepSeek through `langchain-deepseek` (`deepseek-flash` for the baseline; `deepseek-v4-pro` if evaluation shows it is needed)
- Embeddings: `BAAI/bge-small-en-v1.5`, local through fastembed
- Retrieval: hybrid — BM25 + dense embeddings, fused with Reciprocal Rank Fusion, reranked by Jev (TypeSafe) — built from step 9.3 onward
- Vector store: Postgres + pgvector (from step 9.3 onward)
- Tracing and evaluation: LangSmith (project `privy`)

## Commands

```bash
uv run langgraph dev            # dev server + Studio (loads .env)
uv run pytest -q                # tests
uv run ruff check .             # lint
```

## Layout

- `langgraph.json`: tells the server where the graph is (`./src/agent/graph.py:graph`)
- `src/agent/graph.py`: graph entry point
- `corpus/`: the knowledge source (official GDPR text) and the indexing scripts that will build the retrieval index
- `docs/`: see the table under Project
- `tests/`: unit and integration tests

## Secrets

- API keys live only in `.env`, which is git-ignored. Never print, log, or commit key values.
- Keep `.env.example` in sync with the variable names in `.env`, with empty values.

## Code style

- Type hints everywhere.
- No comments that restate what the code does. Comment only non-obvious reasons.

## Git

- Commit only when asked. Never push without explicit approval.
- Commit messages explain why, not just what.
