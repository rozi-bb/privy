## Two corpora — do not confuse them

Privy works with two distinct document collections. They are unrelated and serve different purposes:

| Corpus | Where | Size | Role |
|---|---|---|---|
| **GDPR** | `corpus/` | 404 chunks (173 recitals + 231 article chunks from 99 articles) | The product's knowledge source. Indexed into pgvector and retrieved at runtime. |
| **FiQA** | `practice/fiqa/` | 57,638 docs (financial QA benchmark) | Practice only. Used once (roadmap step 10) to measure NDCG@10 while learning retrieval mechanics. Never imported by `src/agent/`, never indexed, never reaches an answer. |

FiQA is a **labeled benchmark**, not a knowledge source. Its topic (finance) is irrelevant — only its query→relevant-document labels are used, because the GDPR text has no labeled answers of its own. See `docs/architecture.md` §9.

## How we work

The project owner is learning and must be able to explain every part of this codebase in an interview. Optimize for understanding, not speed.

- Before writing code for a feature, explain the plan and the reasoning, then wait for approval.
- After writing, explain each new or changed file in plain language.
- Build one feature at a time. Evaluate it before starting the next.
- Follow the structure generated by the LangGraph template. Do not reorganize it.
- Verify LangChain and LangGraph APIs against the official docs (the `docs-langchain` and `reference-langchain` MCP servers) before using them. This project uses LangChain/LangGraph v1 APIs.

## Stack

- Python 3.13, managed with `uv`
- LangGraph 1.x, LangChain 1.x
- Chat model: DeepSeek through `langchain-deepseek` (`deepseek-flash` for the baseline; `deepseek-v4-pro` if evaluation shows it is needed)
- Embeddings: `BAAI/bge-small-en-v1.5`, local through fastembed
- Retrieval: hybrid — BM25 + dense embeddings, fused with Reciprocal Rank Fusion, reranked by Jev (TypeSafe) — built from roadmap step 11 onward
- Vector store: Postgres + pgvector (from roadmap step 11 onward)
- Tracing and evaluation: LangSmith (project `privy`)

## Commands

```bash
uv run langgraph dev                    # dev server + Studio (loads .env)
docker compose up -d                    # Postgres (pgvector + checkpoints)
uv run python scripts/build_index.py    # build the GDPR index in pgvector
uv run uvicorn backend.main:app --port 8000   # backend
uv run chainlit run src/chat_ui/app.py --port 8001   # chat UI (needs the backend; set BACKEND_URL if not on :8000)
uv run python scripts/create_user.py you@example.com   # create an account (the UI has no sign-up page)
uv run pytest -q tests/unit_tests       # unit tests (free)
uv run pytest -q tests/integration_tests/test_backend_*.py   # backend tests: need Docker Postgres, no API calls (free)
uv run pytest -q tests/integration_tests/test_graph.py       # calls DeepSeek and Jev (costs API credit)
uv run python evals/run.py              # LangSmith evaluation (costs API credit: ~70 DeepSeek + ~460 Jev calls)
uv run ruff check .                     # lint
```

## Layout

- `langgraph.json`: tells the server where the graph is (`./src/agent/graph.py:graph`)
- `src/agent/graph.py`: graph entry point and the generate node
- `src/agent/state.py`: the shared graph state
- `src/agent/corpus.py`: GDPR chunking
- `src/agent/embeddings.py`: local embeddings (fastembed)
- `src/agent/retrieval.py`: BM25 keyword search and RRF fusion
- `src/agent/reranking.py`: Jev reranking and the relevance threshold
- `src/agent/citations.py`: parses citations in an answer and checks them against the passages
- `src/backend/`: the FastAPI backend — `main.py` routes and streaming, `auth.py` passwords and login tokens, `db.py` app-table queries, `schema.sql` app tables, `config.py` settings
- `src/chat_ui/app.py`: the Chainlit chat UI, a pure HTTP client of the backend (never imports the agent or holds provider keys)
- `src/chat_ui/data_layer.py`: serves the sidebar's chat history from the backend; stores nothing itself
- `evals/`: the LangSmith evaluation (`gdpr_dataset.json`, `run.py`)
- `.chainlit/config.toml`, `chainlit.md`: Chainlit settings and welcome text
- `scripts/build_index.py`: chunks the corpus and stores it in pgvector
- `scripts/create_user.py`: creates an account through the backend
- `practice/fiqa/`: the FiQA benchmark pipeline used to learn retrieval mechanics
- `corpus/`: the knowledge source (official GDPR text)
- `docs/`: see the table under Project
- `tests/`: unit and integration tests
